# bw-015: AST mapper bugs — temp_counter, double-add items, unit literal, binary op, number type

**Severity:** Medium  
**Status:** Fixed  
**Files:** Multiple

## Problems

1. **elixir_mapper.ml:30-34** — Module-level `temp_counter` ref never reset per parse. Non-deterministic across files. Fix: `temp_counter := 0` at start of `parse_file`.

2. **crystal_hierarchical_mapper.ml:292-302** — `group_exprs` double-adds def/class/module items when `current_body` is non-empty, and silently drops accumulated body expressions. Fix: finalize body before adding new item.

3. **ocaml_mapper.ml:70** — `()` (unit) mapped to `LBool false` instead of `LUnit`. Fix: separate the cases.

4. **rust_mapper.ml:208** — Binary operator always `"+"` regardless of actual op. Fix: extract operator from tree-sitter text.

5. **javascript_mapper.ml:51** — Numbers mapped to `LString` instead of `LInt`/`LFloat`. Loses type info for taint analysis.
