# bw-022: Trivially weak content hash in incremental engine

**Severity:** Medium  
**Status:** Fixed  
**File:** `lib/catseye_incremental/incremental_graph.ml:56-61`

## Problem

```ocaml
let compute_content_hash content =
  ... Printf.sprintf "%d_%d_%d" len first last
```

Uses only first char + last char + length. Two files with same length, same first/last char hash identically. Incremental engine skips re-analysis when only the middle of a file changes.

## Fix

```ocaml
let compute_content_hash content = Digest.to_hex (Digest.string content)
```
