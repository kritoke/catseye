# bw-001: Crystal parse timeout — hangs on `--cfg --claws --lang crystal`

**Severity:** High  
**Status:** Done (Part A + Part B)  
**Files:** `lib/catseye_ast/crystal_hierarchical_mapper.ml:407-419`, `lib/catseye_ast/crystal_mapper.ml:226`, `lib/catseye_ast/crystal_plugin.ml`

## Problem

`Unix.open_process_in` spawns a Crystal subprocess with **no timeout**. With `--cfg --claws --lang crystal`, each Crystal file is parsed up to **3 times** via separate `crystal run` invocations (flat extraction, CFG path, Claws path). On large files or heavy macro usage, the Crystal compiler can hang, blocking catseye forever.

`cfg_timeout_ms` only covers the CFG build, not the parse step feeding it. `analysis_timeout_ms` defaults to 0 (disabled).

## Fix

### Part A — Per-parse timeout
Replace `Unix.open_process_in` with `Unix.pipe` + `Unix.create_process` + `Unix.select`-based drain with a configurable timeout (15s default). Kill the subprocess on timeout.

### Part B — Cache parsed ASTs in orchestrator
Parse each Crystal file once into `CatseyeAST.t`, cache in a `Hashtbl`, and reuse for CFG + Claws paths. Eliminates 2/3 of Crystal subprocess invocations.

## Reproduction

```bash
catseye --cfg --ai-lint --claws --lang crystal --format terminal src/
# hangs indefinitely on large Crystal projects
```
